# Build a SQL Database Engine from Scratch

Start from an empty folder and write a SQL database that **really persists, queries, and transacts** — in pure JavaScript (Node.js 18+, zero dependencies) — with a ten-chapter tutorial website.

```
Node.js 18+      zero npm packages      pure ESM      playground in the browser
```

---

## What this is

The project has two parts:

1. **A working database engine** (`src/`, `bin/`): parses SQL, executes queries, persists data in pages, writes a transaction journal, and supports transactions.
2. **A tutorial website** (`docs/`): ten chapters that start with "what is a token?" and walk you through building that engine, chapter by chapter.
   Every chapter includes the complete code, runnable checkpoints, tests, and exercises; `steps/` keeps a snapshot of the project at the end of each chapter.

> This is not a SQLite wrapper and not an ORM. Every line is written by hand: tokenizer, parser, query execution, page format, journal, recovery.

## Quickstart

Requires Node.js 18 or newer; no `npm install`.

```bash
# Open an in-memory database (gone when you exit)
node bin/sql.js

# Open (or create) an on-disk database
node bin/sql.js demo.db
```

Inside the REPL:

```sql
CREATE TABLE books (
  id INTEGER PRIMARY KEY,
  title TEXT NOT NULL,
  author TEXT,
  price REAL DEFAULT 0
);

INSERT INTO books (id, title, author, price) VALUES
  (1, 'JavaScript: The Good Parts', 'Douglas Crockford', 320),
  (2, 'Designing Data-Intensive Applications', 'Martin Kleppmann', 680);

SELECT author, COUNT(*) AS n, SUM(price) AS total
FROM books
GROUP BY author
ORDER BY total DESC;
```

Built-in commands: `.help`, `.tables`, `.schema`, `.mode table|json`, `.tokens`, `.ast`, `.open`, `.read`, `.exit`.

You can also batch-execute a SQL file:

```bash
node bin/sql.js examples/demo.db < examples/demo.sql
```

## Tutorial website

`docs/` is a purely static site with no CDN and no external fonts — double-click it and read:

```bash
# Open it directly
start docs/index.html

# Or run a local server (recommended: the playground is less restricted over HTTP)
node tools/serve.mjs
# http://localhost:8080/docs/
```

The site includes:

- **Ten chapters**: concepts, complete source files, diffs between steps, checkpoints, exercises, and vocabulary.
- **SQL Playground** (`docs/playground.html`): the engine bundled for the browser — create tables, query, GROUP BY, and JOIN.
- **Syntax Reference** (`docs/reference.html`): supported syntax, functions, error codes, and CLI commands.
- A calm warm-beige reading theme with an optional dark mode, reading progress, chapter completion, search, and an on-page table of contents.

The site is generated by `tools/build-docs.mjs` from `docs/content/` and `steps/`:

```bash
node tools/build-docs.mjs
```

## Ten-chapter roadmap

| Chapter | Topic | What you end up with |
| --- | --- | --- |
| 01 | Orientation and skeleton | Project layout, REPL loop |
| 02 | Lexical analysis | `tokenizer.js`, `errors.js` |
| 03 | Parsing | `parser.js`: CREATE / INSERT / SELECT, expression precedence |
| 04 | Values and types | `values.js`: three-valued logic, type affinity, LIKE |
| 05 | Storage layer | `schema.js`, `table.js`, `storage/memory.js`, `database.js` |
| 06 | SELECT pipeline | `engine/expr.js`, `engine/query.js`, `engine/write.js`, a CLI that really queries |
| 07 | Aggregation and grouping | `engine/aggregate.js`, GROUP BY / HAVING |
| 08 | Updates and deletes | UPDATE / DELETE, statement atomicity |
| 09 | JOIN | INNER / LEFT JOIN, nested loops, ambiguous columns |
| 10 | Persistence and transactions | Page format, catalog, heap, CRC32 journal, crash recovery, BEGIN / COMMIT / ROLLBACK |

The complete project at the end of each chapter lives in `steps/01-skeleton` … `steps/10-persistence`, and each one runs on its own:

```bash
cd steps/06-select
node bin/sql.js < ../demo.sql   # or node --test
```

## Supported SQL

- `CREATE TABLE` / `DROP TABLE` (primary keys, NOT NULL, UNIQUE, DEFAULT, composite primary keys and UNIQUE constraints)
- `INSERT` (multi-row and explicit columns), `UPDATE`, `DELETE`
- `SELECT`: `WHERE`, `ORDER BY`, `LIMIT / OFFSET`, `DISTINCT`, `GROUP BY`, `HAVING`, `INNER / LEFT JOIN`
- Expressions: comparisons, arithmetic, `AND / OR / NOT`, `LIKE`, `IN`, `BETWEEN`, `IS [NOT] NULL`, `||`
- Aggregates: `COUNT(*)`, `COUNT(x)`, `COUNT(DISTINCT x)`, `SUM`, `AVG`, `MIN`, `MAX`
- Scalar functions: `UPPER`, `LOWER`, `LENGTH`, `TRIM`, `ABS`, `ROUND`, `COALESCE`, `IFNULL`, `TYPEOF`, `REPLACE`, `SUBSTR`
- Transactions: `BEGIN` / `COMMIT` / `ROLLBACK`

See `docs/reference.html` for the complete list and the syntax details.

## Examples

`examples/` contains two SQL scripts you can run immediately:

```bash
node bin/sql.js examples/demo.db < examples/demo.sql
node bin/sql.js examples/join.db < examples/join.sql
```

The first run creates the database file; the second run fails because the tables already exist (that is expected).
Delete the `.db` files to start over.

## Design trade-offs (tutorial edition)

This database is built for understanding, not as a production replacement. The deliberate simplifications:

| Trade-off | Why | If you want to go further |
| --- | --- | --- |
| The whole database lives in memory | Simple query logic, easy to debug | Add a page cache and lazy page loading |
| Every commit rewrites all tables | Hard to get wrong | Write only dirty pages, add checkpoints |
| No indexes, full table scans | Keeps the chapter scope small | Start with a primary-key hash index, then attempt a B+tree |
| Single process, no locking | No concurrency control needed | File locks, MVCC, WAL LSNs |
| No query planner | Fixed pipeline order | EXPLAIN, cost estimates, choose the driving table |
| Subqueries / UNION / ALTER TABLE unsupported | Scope control | All excellent next exercises |

These limits are not defects; they are the next set of problems. Chapter 10 ends with a full list of extensions.

## Publishing it on GitHub

The repository is ready for GitHub: MIT license, `.gitignore`, a test CI workflow and a GitHub Pages deployment workflow are included.

See [PUBLISHING.md](PUBLISHING.md) for the full walkthrough - install and configure Git, authenticate, create the repository, make the first commit, push, and publish the tutorial site.

Short version (after creating an empty repository on GitHub):

```bash
git init -b main                 # already done in this workspace
git add .
git commit -m "Initial commit: SQL engine and ten-chapter tutorial site"
git remote add origin https://github.com/<your-username>/<repo>.git
git push -u origin main
```

Then enable **Settings -> Pages -> Source: GitHub Actions** and the site goes live at `https://<your-username>.github.io/<repo>/`.
