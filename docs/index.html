01 — Why

Why build a database yourself?

You use databases every day, yet you rarely get to open one up. Courses teach normalization and ACID; tools hand you connection strings and ORMs. The long middle — how rows actually reach the disk, how a query gets decomposed, how a transaction avoids doing only half its work — is usually left blank.

Write one yourself and those nouns turn into concrete code. You will see why a row cannot grow without limit, why an index speeds up reads and slows down writes, and why a database can still come back consistent after a crash. Those intuitions last longer than any definition you can memorize.

The barrier is lower than it looks: a computer with Node.js, a text editor, and ten chapters. No third-party packages, no database to install, no cloud service. You decide where every byte comes from and where it goes.

By the end you have a working database: open a file, create tables, insert, query, and run transactions, all through a command-line interface. It is not a production replacement, but it is a database you genuinely understand.

04 — Quickstart

Quickstart

One requirement: Node.js 18 or newer. No npm install and no database server.

Run it

Open a terminal, enter the project folder, create a database file, and start the shell.

# Requires Node.js 18+
cd SQL
node bin/sql.js demo.db

# interactive mode
sql> SELECT 1 + 1;
2

Read it

The site is static files: double-click docs/index.html to read, or start a local server to use the playground.

# dependency-free static server
node tools/serve.mjs

# → http://localhost:8080/docs/

The playground needs docs/assets/sql-engine.js; it appears after you run the build.

05 — Structure

Project structure

The engine, the CLI, the tutorial content, and the website stay separate and independent.

SQL/
├── bin/              # command-line entry point
│   └── sql.js        # node bin/sql.js demo.db
├── src/              # engine: storage, parsing, execution, transactions
├── tests/            # acceptance tests for every chapter
├── steps/            # progressive snapshots, one per chapter
├── tools/
│   ├── build-docs.mjs # content → HTML, plus toc.js
│   └── serve.mjs      # dependency-free static server
└── docs/             # this website
    ├── index.html
    ├── playground.html
    ├── content/       # chapter sources
    ├── chapters/      # generated chapter pages
    └── assets/        # style.css, site.js, playground

06 — Audience

Who this tutorial is for

01 / Some programming experience

Variables, functions, and loops are enough

No database experience needed, and no C or operating-systems background. Every step starts from the smallest runnable program.

02 / Curious about the black box

Interested in how it actually works underneath

You will work directly with bytes, pages, cursors, the AST, and the transaction journal instead of calling a ready-made API.

03 / Hands-on learner

Every chapter has a verifiable checkpoint

Each concept ships with runnable code and expected output; if it runs and matches, the chapter is done.
