Chapter 08 / Updates and deletes

Making data move: UPDATE / DELETE and statement atomicity

So far we can only add data. This chapter adds modification and deletion, and handles a problem that's easy to overlook: if an UPDATE violates a constraint on the fifth row, should the changes to the first four rows stay? The answer is no.

How UPDATE works

  1. Find the target table, then check that every SET column exists (so a typo doesn't surface halfway through).
  2. Scan all rows and filter with the WHERE condition; with no WHERE, that's every row.
  3. Compute the new values for each row. Note: every assignment sees the old values.
  4. Hand the new values to Table.update(), which checks constraints and writes them back.

The third point matters. Consider this example: 

UPDATE books SET price = 1, stock = stock + 10 WHERE id = 2;

If we set price to 1 first and then compute stock + 10, the result doesn't change; but if the two assignments reference each other (SET a = b, b = a, a swap), the order affects the result. The SQL spec says: every value in one UPDATE is computed from the pre-change row. Our implementation computes the whole patch first and then hands it to Table in one go, so it gets this semantics for free.

How DELETE works

Filter the rows that match WHERE, then delete them one by one. Rows live in a Map keyed by rowid, so deletion is O(1). Deleted rowids are never reused, so "delete then insert" won't resurrect an old identifier.

Statement atomicity: roll the whole thing back on failure

Picture UPDATE books SET id = 1 WHERE id >= 2: changing the first row to 1 is fine, but the second hits the PRIMARY KEY. Without rollback, the database would be left in a half-updated state.

We already put the guard in Database.exec() in Chapter 6: take a snapshot before every statement, and call loadSnapshot() on error. This chapter just applies the same mechanism to the new statements and confirms with tests that it really works.

The cost of snapshots

Copying the whole database for every statement is fine at small data sizes, but it's wasteful. Chapter 10 uses "remember only the pages that changed" plus a transaction journal to do this efficiently — that's why real databases need a WAL / journal.

src/engine/write.js: add UPDATE / DELETE

  /**
   * Execution of write statements: CREATE TABLE, DROP TABLE, INSERT
   *
   * Actual data changes are handled by Table (src/table.js); this file only:
   *   1. finds the target table from the AST
   *   2. evaluates AST expressions to values
   *   3. builds the object Table.insert() expects
   *   4. returns a uniform execution result
   *
   * UPDATE / DELETE live here too: their flow is similar to INSERT, except they first find
   * rows matching WHERE, then rewrite them one by one.
   */
  import { SqlError } from "../errors.js";
  import { buildTableSchema, findColumn } from "../schema.js";
  import { evaluate } from "./expr.js";
  import { truthy } from "../values.js";
  
  /** Create a uniform "command result" object. */
  export function commandResult(message, { changes = 0, lastInsertRowid = null } = {}) {
    return { type: "command", message, changes, lastInsertRowid };
  }
  
  export function executeCreateTable(db, ast) {
    if (db.hasTable(ast.name)) {
      if (ast.ifNotExists) {
        return commandResult("Table " + ast.name + " already exists, skipped");
      }
      throw new SqlError("Table already exists: " + ast.name, {
        code: "SCHEMA_ERROR",
        hint: "Use CREATE TABLE IF NOT EXISTS if you do not want an error.",
      });
    }
    const schema = buildTableSchema(ast);
    db.createTable(schema);
    return commandResult(
      "Created table " + schema.name + " (" + schema.columns.length + " columns)"
    );
  }
  
  export function executeDropTable(db, ast) {
    if (!db.hasTable(ast.name)) {
      if (ast.ifExists) return commandResult("Table " + ast.name + " does not exist, skipped");
      throw new SqlError("Table does not exist: " + ast.name, {
        code: "SCHEMA_ERROR",
        hint: db.listTables().length > 0 ? "Existing tables: " + db.listTables().join(", ") : null,
      });
    }
    db.dropTable(ast.name);
    return commandResult("Dropped table " + ast.name);
  }
  
  export function executeInsert(db, ast) {
    const table = db.getTable(ast.table);
  
    // Decide which columns to write: use an explicit column list if given, otherwise all columns (in schema order).
    const columns = ast.columns
      ? ast.columns.map((name) => {
          const column = findColumn(table.schema, name);
          if (!column) {
            throw new SqlError("Table " + table.name + " has no column " + name, {
              code: "SCHEMA_ERROR",
              hint: "Available columns: " + table.columns.map((column) => column.name).join(", "),
            });
          }
          return column.name;
        })
      : table.columns.map((column) => column.name);
  
    const seen = new Set();
    for (const name of columns) {
      const key = name.toLowerCase();
      if (seen.has(key)) {
        throw new SqlError("Duplicate column in INSERT column list: " + name, { code: "SYNTAX_ERROR" });
      }
      seen.add(key);
    }
  
    let changes = 0;
    let lastInsertRowid = null;
  
    for (const valueExprs of ast.rows) {
      if (valueExprs.length !== columns.length) {
        throw new SqlError(
          "Column count and value count differ: " + columns.length + " columns, " + valueExprs.length + " values",
          { code: "SYNTAX_ERROR" }
        );
      }
      const values = {};
      for (let i = 0; i < columns.length; i++) {
        // INSERT values cannot reference columns, so the source list is empty.
        values[columns[i]] = evaluate(valueExprs[i], [], {});
      }
      const row = table.insert(values);
      changes += 1;
      lastInsertRowid = row.__rowid;
    }
  
    return commandResult("Inserted " + changes + " rows into " + table.name, {
      changes,
      lastInsertRowid,
    });
  }
  
  export function executeUpdate(db, ast) {
    const table = db.getTable(ast.table);
  
    // Validate all SET columns up front so we do not fail halfway through.
    const columns = new Map();
    for (const assignment of ast.assignments) {
      const column = findColumn(table.schema, assignment.column);
      if (!column) {
        throw new SqlError("Table " + table.name + " has no column " + assignment.column, {
          code: "SCHEMA_ERROR",
          hint: "Available columns: " + table.columns.map((item) => item.name).join(", "),
        });
      }
      const key = column.name.toLowerCase();
      if (columns.has(key)) {
        throw new SqlError("UPDATE assigns the same column twice: " + column.name, { code: "SYNTAX_ERROR" });
      }
      columns.set(key, assignment);
    }
  
    const matches = table
      .all()
      .filter((values) => matchesWhere(ast.where, table, values));
  
    let changes = 0;
    for (const values of matches) {
      // All changes to a row apply "simultaneously": every expression sees the old values.
      const patch = {};
      for (const [key, assignment] of columns) {
        patch[assignment.column] = evaluate(assignment.value, sourcesFor(table, values), {});
        void key;
      }
      table.update(values.__rowid, patch);
      changes += 1;
    }
  
    return commandResult("Updated " + changes + " rows (" + table.name + ")", { changes });
  }
  
  export function executeDelete(db, ast) {
    const table = db.getTable(ast.table);
    const matches = table
      .all()
      .filter((values) => matchesWhere(ast.where, table, values));
  
    let changes = 0;
    for (const values of matches) {
      if (table.delete(values.__rowid)) changes += 1;
    }
  
    return commandResult("Deleted " + changes + " rows (" + table.name + ")", { changes });
  }
  
  /** Wrap a row as the source list expected by expression evaluation. */
  function sourcesFor(table, values) {
    return [{ alias: table.name, table, values }];
  }
  
  /** An empty WHERE means "all rows"; NULL / UNKNOWN never match. */
  function matchesWhere(where, table, values) {
    if (!where) return true;
    return truthy(evaluate(where, sourcesFor(table, values), {}));
  }

Finally, wire the new statements into the executor:

src/engine/executor.js: dispatch UPDATE / DELETE

  /**
   * Executor: dispatch AST nodes to the corresponding executors
   *
   * Every statement node the parser produces maps to an execution function here.
   * This file is intentionally thin so it is obvious which statements are supported.
   */
  import { SqlError } from "../errors.js";
  import { executeSelect } from "./query.js";
  import {
    executeCreateTable,
    executeDelete,
    executeDropTable,
    executeInsert,
    executeUpdate,
  } from "./write.js";
  
  /**
   * Execute one statement and return a result object.
   *
   * Result for SELECT:
   *   { type: "select", columns: [{name, type}], rows: [[...]], rowCount }
   *
   * Results for other statements:
   *   { type: "command", message, changes, lastInsertRowid }
   *
   * @param {import("../database.js").Database} db
   * @param {object} ast
   */
  export function execute(db, ast) {
    switch (ast.type) {
      case "select":
        return executeSelect(db, ast);
      case "insert":
        return executeInsert(db, ast);
      case "create_table":
        return executeCreateTable(db, ast);
      case "drop_table":
        return executeDropTable(db, ast);
      case "update":
        return executeUpdate(db, ast);
      case "delete":
        return executeDelete(db, ast);
      case "begin":
      case "commit":
      case "rollback":
        throw new SqlError("Transactions are not implemented yet (added in chapter 10)", { code: "NOT_SUPPORTED" });
      default:
        throw new SqlError("Cannot execute statement: " + ast.type, { code: "INTERNAL_ERROR" });
    }
  }

Tests: don't let half-finished changes survive

Beyond basic updates and deletes, the tests check two things in particular: old-value semantics across multiple assignments, and full-statement rollback when a constraint is violated.

tests/write.test.jsJavaScript · 69 lines · step 8
import test from "node:test";
import assert from "node:assert/strict";
import { Database } from "../src/database.js";

function makeDb() {
  const db = new Database();
  db.exec("CREATE TABLE books (id INTEGER PRIMARY KEY, title TEXT, price REAL, stock INTEGER DEFAULT 0);");
  db.exec("INSERT INTO books VALUES (1, 'JS', 100, 5), (2, 'DB', 200, 3), (3, 'OS', 150, 0);");
  return db;
}

test("UPDATE: targeted rows, expressions, old-value semantics", () => {
  const db = makeDb();
  const [result] = db.exec("UPDATE books SET price = price * 2 WHERE id = 1");
  assert.equal(result.changes, 1);
  assert.deepEqual(db.query("SELECT price FROM books WHERE id = 1").rows, [[200]]);

  // every assignment in one UPDATE sees the old value
  const db2 = makeDb();
  db2.exec("UPDATE books SET price = 1, stock = stock + 10 WHERE id = 2");
  assert.deepEqual(db2.query("SELECT price, stock FROM books WHERE id = 2").rows, [[1, 13]]);
});

test("UPDATE without WHERE touches every row", () => {
  const db = makeDb();
  const [result] = db.exec("UPDATE books SET stock = 0");
  assert.equal(result.changes, 3);
  assert.deepEqual(db.query("SELECT DISTINCT stock FROM books").rows, [[0]]);
});

test("UPDATE leaves rows that fail WHERE untouched", () => {
  const db = makeDb();
  const [result] = db.exec("UPDATE books SET stock = 99 WHERE price > 120");
  assert.equal(result.changes, 2); // both 200 and 150 exceed 120
  assert.deepEqual(db.query("SELECT id, stock FROM books ORDER BY id").rows, [[1, 5], [2, 99], [3, 99]]);
});

test("a constraint violation in UPDATE reverts the whole statement", () => {
  const db = makeDb();
  assert.throws(() => db.exec("UPDATE books SET id = 1 WHERE id >= 2"), /PRIMARY KEY/);
  assert.deepEqual(db.query("SELECT id FROM books ORDER BY id").rows, [[1], [2], [3]]);
});

test("UPDATE on a missing column or table", () => {
  const db = makeDb();
  assert.throws(() => db.exec("UPDATE books SET nope = 1"), /no column/);
  assert.throws(() => db.exec("UPDATE nope SET a = 1"), /does not exist/);
});

test("DELETE: conditional and full delete", () => {
  const db = makeDb();
  const [result] = db.exec("DELETE FROM books WHERE price >= 150");
  assert.equal(result.changes, 2);
  assert.deepEqual(db.query("SELECT id FROM books").rows, [[1]]);

  const [all] = db.exec("DELETE FROM books");
  assert.equal(all.changes, 1);
  assert.equal(db.query("SELECT * FROM books").rowCount, 0);
  assert.equal(db.query("SELECT COUNT(*) FROM books").rows[0][0], 0);
});

test("rowids are not reused after DELETE", () => {
  const db = new Database();
  db.exec("CREATE TABLE t (a TEXT)");
  db.exec("INSERT INTO t VALUES ('x')");
  db.exec("DELETE FROM t");
  db.exec("INSERT INTO t VALUES ('y')");
  assert.equal(db.query("SELECT * FROM t").rows.length, 1);
});

Chapter recap

  • UPDATE computes the new row in full before writing it back; every assignment uses the old values.
  • DELETE filters by WHERE and removes rows one by one; rowids are never reused.
  • A statement is an atomic unit: on failure the whole statement rolls back, leaving no partial changes.

Exercises

  1. Support UPDATE ... LIMIT 10 (MySQL has it; standard SQL doesn't).
  2. Make DELETE return the list of deleted rowids for easier debugging.
  3. Compare "snapshot first" and "validate all rows before writing" as two approaches to atomicity. What are the tradeoffs?

Chapter glossary

Atomicity
An operation either fully succeeds or doesn't happen at all.
Rollback
Restoring data to its state before the operation.
Old-value semantics
Every computation in one UPDATE uses the pre-change row.
