Chapter 02 / Lexing

Cutting SQL into tokens: the tokenizer

A computer doesn't understand the word "SELECT"; it only sees a stream of characters. The tokenizer's job is to cut that stream into human-defined units and record where each unit appeared in the source text. It's the first step of the whole compile pipeline, and the best one to warm up on.

The input and output we want

Here's a piece of SQL:

SELECT name, COUNT(*) FROM books WHERE price >= 100; -- find the pricier books

The output is an array of tokens (type, value, position):

[
  { type: "word",   value: "SELECT", upper: "SELECT", line: 1, column: 1 },
  { type: "word",   value: "name",   line: 1, column: 8 },
  { type: "punct",  value: ",",      line: 1, column: 12 },
  { type: "word",   value: "COUNT",  upper: "COUNT", line: 1, column: 14 },
  ...
  { type: "eof",    value: "",       line: 1, column: 60 }
]

Notice a few things: comments never become tokens, strings lose their quotes, keywords always get an upper field for easy comparison later, and the array always ends with an eof. All of these choices make the parser easier to write.

Write the error type first: error messages are part of the product

Before writing the tokenizer, create a shared error class. A good database tells you "line 3, column 15: missing closing parenthesis" instead of throwing a bare Unexpected token.

SqlError carries three fields: a stable code (so code can branch on the kind of error), position (offset / line / column), and an optional hint (how to fix it). Its format(sql) method renders the error with a caret: 

SYNTAX_ERROR: expected an expression but found ';'
 1 | SELECT * FROM books WHERE ;
   |                          ^
Hint: ...
src/errors.jsJavaScript · 57 lines · step 2
/**
 * All SQL errors are wrapped in SqlError.
 *
 * A good database error message should tell the user three things:
 *   1. where it failed (offset / line / column)
 *   2. which character is wrong (print the offending SQL snippet and point at it with ^)
 *   3. how to fix it (optional hint)
 *
 * This class is shared by the tokenizer, parser, and executor across the project.
 */
export class SqlError extends Error {
  /**
   * @param {string} message human-readable error message
   * @param {object} [options]
   * @param {string} [options.code] stable error code for programmatic checks (e.g. SYNTAX_ERROR)
   * @param {{offset:number, line:number, column:number}|null} [options.position]
   * @param {string|null} [options.hint] suggested fix
   */
  constructor(message, { code = "SQL_ERROR", position = null, hint = null } = {}) {
    super(message);
    this.name = "SqlError";
    this.code = code;
    this.position = position;
    this.hint = hint;
  }

  /**
   * Format the error as a multi-line string suitable for printing in a terminal:
   *
   *   SYNTAX_ERROR: expected ...
   *     SELECT * FROM
   *                  ^
   *   hint: ...
   */
  format(source) {
    const lines = [`${this.code}: ${this.message}`];
    if (source && this.position) {
      const { line, column } = this.position;
      const text = source.split(/\r?\n/)[line - 1] ?? "";
      const gutter = String(line).length;
      lines.push(`${" ".repeat(gutter)} |`);
      lines.push(`${line} | ${text}`);
      lines.push(`${" ".repeat(gutter)} | ${" ".repeat(Math.max(0, column - 1))}^`);
    }
    if (this.hint) lines.push(`Hint: ${this.hint}`);
    return lines.join("\n");
  }
}

/** Convenience helper for creating syntax errors. */
export function syntaxError(message, token, hint = null) {
  return new SqlError(message, {
    code: "SYNTAX_ERROR",
    position: token ? { offset: token.start, line: token.line, column: token.column } : null,
    hint,
  });
}

Scanning: move forward one character at a time

The most direct implementation is a while loop with an index i: look at the current character and decide how many characters to consume. That's a small state machine.

What you seeActionEmits token
Whitespace, newlineAdvance and update the line counterNo
--Consume to end of lineNo
/*Consume through */No
'...'Handle '' escapingstring
Starts with a digitRead integer / decimal / exponentnumber
Letter or _Read the whole identifierword
+ - * / % = < > !Try the two-character operator first (>=)op
( ) , ; .Single characterpunct

Two easy traps: first, compare operators longest-first, or >= is split into > and =. Second, record the position before consuming characters, or the error message points at the next character.

src/tokenizer.jsJavaScript · 286 lines · step 2
/**
 * Tokenizer / Lexer
 *
 * Split a SQL string into tokens. This layer only recognizes tokens;
 * it does not understand grammar, so it is simple and easy to test:
 *
 *   SELECT name FROM books WHERE price > 100;
 *
 *   -> word(SELECT) word(name) word(FROM) word(books) word(WHERE)
 *      word(price) op(>) number(100) punct(;)
 *
 * Design notes:
 *   - each token records its position in the source string (offset/line/column),
 *     so error messages can point at the exact spot.
 *   - keywords get no special token type; they are all words, and the parser checks upper.
 *     This lets keywords be used as column names (when double-quoted) and keeps the implementation simple.
 *   - supports line comments, block comments, single-quoted strings, and double-quoted/backtick identifiers.
 */
import { SqlError } from "./errors.js";

/** Keyword table: the parser uses it to decide whether a word is a reserved word. */
export const KEYWORDS = new Set(
  `SELECT FROM WHERE GROUP BY HAVING ORDER LIMIT OFFSET
   INSERT INTO VALUES UPDATE SET DELETE CREATE TABLE DROP
   IF NOT EXISTS PRIMARY KEY UNIQUE DEFAULT NULL AND OR AS DISTINCT
   JOIN INNER LEFT OUTER ON USING BEGIN COMMIT ROLLBACK TRANSACTION
   TRUE FALSE IS LIKE BETWEEN IN ASC DESC INTEGER INT REAL TEXT BLOB
   NUMERIC BOOLEAN CHAR VARCHAR`.split(/\s+/).filter(Boolean)
);

/** Single-character punctuation. */
const PUNCTUATION = new Set(["(", ")", ",", ";", "."]);

/** Sorted longest-first so '>=' is not split into '>' and '='. */
const OPERATORS = ["||", "<=", ">=", "<>", "!=", "==", "=", "<", ">", "+", "-", "*", "/", "%"];

/** @typedef {"word"|"number"|"string"|"punct"|"op"|"eof"} TokenType */

/**
 * @typedef {object} Token
 * @property {TokenType} type
 * @property {string} value    decoded value (strings are unquoted; words keep the original text)
 * @property {string} text     raw text (used in error messages)
 * @property {string} [upper]  uppercase form of word, for keyword comparison
 * @property {boolean} [quoted] whether the identifier is wrapped in "..." or `...`
 * @property {number} start    starting offset in the source string
 * @property {number} end      end offset (exclusive)
 * @property {number} line     1-based line number
 * @property {number} column   1-based column number
 */

/**
 * Split SQL into an array of tokens; the last token is always eof.
 * @param {string} source
 * @returns {Token[]}
 */
export function tokenize(source) {
  const tokens = [];
  let i = 0;
  let line = 1;
  let lineStart = 0; // offset where the current line starts, used to compute column

  const columnAt = (offset) => offset - lineStart + 1;

  /** Advance one character and maintain the line number. */
  const advance = (count = 1) => {
    for (let k = 0; k < count; k++) {
      if (source[i] === "\n") {
        line += 1;
        lineStart = i + 1;
      }
      i += 1;
    }
  };

  const makeToken = (type, value, start, extra = {}) => ({
    type,
    value,
    text: source.slice(start, i),
    start,
    end: i,
    line: startLine,
    column: startColumn,
    ...extra,
  });

  /** Scan from the current position to end of line, skipping a -- comment. */
  const skipLineComment = () => {
    while (i < source.length && source[i] !== "\n") advance();
  };

  const skipBlockComment = (start, startLine, startColumn) => {
    advance(2); // consume /*
    while (i < source.length) {
      if (source[i] === "*" && source[i + 1] === "/") {
        advance(2);
        return;
      }
      advance();
    }
    throw new SqlError("unterminated block comment (missing */)", {
      code: "SYNTAX_ERROR",
      position: { offset: start, line: startLine, column: startColumn },
    });
  };

  let startLine = 1;
  let startColumn = 1;

  while (i < source.length) {
    const ch = source[i];

    // --- whitespace ---
    if (ch === " " || ch === "\t" || ch === "\r" || ch === "\n") {
      advance();
      continue;
    }

    startLine = line;
    startColumn = columnAt(i);
    const start = i;

    // --- comments ---
    if (ch === "-" && source[i + 1] === "-") {
      skipLineComment();
      continue; // comments are not tokens
    }
    if (ch === "/" && source[i + 1] === "*") {
      skipBlockComment(start, startLine, startColumn);
      continue;
    }

    // --- strings: '...', two consecutive single quotes stand for one single quote ---
    if (ch === "'") {
      advance(); // opening quote
      let value = "";
      let closed = false;
      while (i < source.length) {
        const c = source[i];
        if (c === "'") {
          if (source[i + 1] === "'") {
            value += "'";
            advance(2);
            continue;
          }
          advance(); // closing quote
          closed = true;
          break;
        }
        value += c;
        advance();
      }
      if (!closed) {
        throw new SqlError("unterminated string (missing closing quote)", {
          code: "SYNTAX_ERROR",
          position: { offset: start, line: startLine, column: startColumn },
        });
      }
      tokens.push(makeToken("string", value, start));
      continue;
    }

    // --- identifier / keyword: double-quoted or backticked forms may contain spaces ---
    if (ch === '"' || ch === "`") {
      const quote = ch;
      advance();
      let value = "";
      let closed = false;
      while (i < source.length) {
        const c = source[i];
        if (c === quote) {
          if (source[i + 1] === quote) {
            value += quote;
            advance(2);
            continue;
          }
          advance();
          closed = true;
          break;
        }
        value += c;
        advance();
      }
      if (!closed) {
        throw new SqlError(`unterminated identifier (missing ${quote})`, {
          code: "SYNTAX_ERROR",
          position: { offset: start, line: startLine, column: startColumn },
        });
      }
      tokens.push(makeToken("word", value, start, { upper: value.toUpperCase(), quoted: true }));
      continue;
    }

    // --- numbers: 12, 3.14, .5, 1e3, 2.5E-2 ---
    if (isDigit(ch) || (ch === "." && isDigit(source[i + 1]))) {
      while (isDigit(source[i])) advance();
      if (source[i] === "." ) {
        advance();
        while (isDigit(source[i])) advance();
      }
      if (source[i] === "e" || source[i] === "E") {
        const save = i;
        advance();
        if (source[i] === "+" || source[i] === "-") advance();
        if (!isDigit(source[i])) {
          i = save; // not an exponent, rewind (e.g. 1e followed by whitespace)
        } else {
          while (isDigit(source[i])) advance();
        }
      }
      tokens.push(makeToken("number", source.slice(start, i), start));
      continue;
    }

    // --- identifier / keyword ---
    if (isIdentStart(ch)) {
      while (isIdentPart(source[i])) advance();
      const value = source.slice(start, i);
      tokens.push(makeToken("word", value, start, { upper: value.toUpperCase() }));
      continue;
    }

    // --- punctuation ---
    if (PUNCTUATION.has(ch)) {
      advance();
      tokens.push(makeToken("punct", ch, start));
      continue;
    }

    // --- operators (try the two-character forms first) ---
    const two = source.slice(i, i + 2);
    if (OPERATORS.includes(two)) {
      advance(2);
      tokens.push(makeToken("op", two, start));
      continue;
    }
    if (OPERATORS.includes(ch)) {
      advance();
      tokens.push(makeToken("op", ch, start));
      continue;
    }

    // --- anything else is unrecognized ---
    throw new SqlError(`unrecognized character '${ch}'`, {
      code: "SYNTAX_ERROR",
      position: { offset: start, line: startLine, column: startColumn },
    });
  }

  tokens.push({
    type: "eof",
    value: "",
    text: "",
    start: i,
    end: i,
    line,
    column: columnAt(i),
  });
  return tokens;
}

function isDigit(ch) {
  return ch !== undefined && ch >= "0" && ch <= "9";
}

function isIdentStart(ch) {
  return ch !== undefined && (ch === "_" || (ch >= "a" && ch <= "z") || (ch >= "A" && ch <= "Z") || ch.charCodeAt(0) > 127);
}

function isIdentPart(ch) {
  return isIdentStart(ch) || isDigit(ch) || ch === "$";
}

/**
 * Turn a chunk of SQL into a human-readable token summary; the REPL's .tokens command uses it.
 * @param {string} sql
 */
export function describeTokens(sql) {
  return tokenize(sql)
    .map((t) => {
      if (t.type === "eof") return "eof";
      const value = t.type === "string" ? JSON.stringify(t.value) : t.text;
      return `${t.type}(${value})`;
    })
    .join(" ");
}

How are line and column numbers computed?

We only need to remember where the current line starts (lineStart). The current column = current offset − lineStart + 1. Every time we consume a newline, increment line and set lineStart to the position of the next character.

This approach doesn't need to scan the whole document up front, and it won't miscount on CJK text or emoji, because we measure the offset, not the visual width. Terminal display is a separate concern (chapter 6's table output handles full-width characters).

Why don't keywords get their own token type?

Some tutorials tag SELECT as KEYWORD and everything else as IDENTIFIER. We deliberately don't: everything is a word, and the layer above checks it with upper. The benefits:

  • The tokenizer doesn't need to know how many keywords SQL has (though we still keep a keyword table for the parser).
  • Supporting "use a double-quoted reserved word as a column name" is easy: a word with quoted: true doesn't take part in keyword comparison.
  • When new syntax arrives later (for example RETURNING), the tokenizer barely changes.

Why not just split with a regular expression?

sql.split(/\s+/) or one big regex works for simple cases, but you'll soon hit whitespace inside strings ('hello world'), semicolons inside comments, escape characters, and so on. A hand-written scanner is a bit more code, but every branch is visible and errors are easy to locate.

Make the tokenizer visible in the REPL

Add a .tokens <SQL> command to the CLI. It's a great debugging tool: when the parser misbehaves later, check the tokens first — that usually narrows things down. 

.tokens SELECT name FROM books WHERE price >= 100
word(SELECT) word(name) word(FROM) word(books) word(WHERE) word(price) op(>=) number(100) eof

Tests: write them first, then trust the code

The tokenizer is the easiest part to unit-test: the input is a string, the output is plain data, and there are no side effects. The tests below cover keyword case, number formats, string escaping, comments, positions, and errors.

tests/tokenizer.test.jsJavaScript · 90 lines · step 2
import test from "node:test";
import assert from "node:assert/strict";
import { tokenize, describeTokens } from "../src/tokenizer.js";
import { SqlError } from "../src/errors.js";

const types = (sql) => tokenize(sql).map((t) => t.type);
const values = (sql) => tokenize(sql).filter((t) => t.type !== "eof").map((t) => t.value);

test("an empty string yields only eof", () => {
  const tokens = tokenize("");
  assert.equal(tokens.length, 1);
  assert.equal(tokens[0].type, "eof");
});

test("a basic SELECT tokenizes into the right tokens", () => {
  assert.deepEqual(values("SELECT name FROM books"), ["SELECT", "name", "FROM", "books"]);
  assert.deepEqual(types("SELECT name FROM books"), ["word", "word", "word", "word", "eof"]);
});

test("keywords are case-insensitive and upper is always uppercase", () => {
  const tokens = tokenize("select SeLeCt from");
  assert.equal(tokens[0].upper, "SELECT");
  assert.equal(tokens[1].upper, "SELECT");
  assert.equal(tokens[2].upper, "FROM");
});

test("numbers: integer, decimal, exponent", () => {
  const tokens = tokenize("1 3.14 .5 2.5e3 1E-2");
  assert.deepEqual(tokens.slice(0, -1).map((t) => t.value), ["1", "3.14", ".5", "2.5e3", "1E-2"]);
  assert.ok(tokens.slice(0, -1).every((t) => t.type === "number"));
});

test("strings support single-quote escapes", () => {
  const tokens = tokenize("'it''s ok'");
  assert.equal(tokens[0].type, "string");
  assert.equal(tokens[0].value, "it's ok");
  assert.equal(tokens[0].text, "'it''s ok'");
});

test("double quotes and backticks can wrap whitespace and keywords", () => {
  const tokens = tokenize('"my column" `from`');
  assert.equal(tokens[0].value, "my column");
  assert.equal(tokens[0].quoted, true);
  assert.equal(tokens[1].value, "from");
  assert.equal(tokens[1].quoted, true);
});

test("line and block comments are ignored", () => {
  assert.deepEqual(values("SELECT 1 -- this is a comment\nFROM t"), ["SELECT", "1", "FROM", "t"]);
  assert.deepEqual(values("SELECT /* multi-line\ncomment */ 2"), ["SELECT", "2"]);
});

test("operators are matched longest first", () => {
  assert.deepEqual(values("a >= b <> c != d || e"), ["a", ">=", "b", "<>", "c", "!=", "d", "||", "e"]);
});

test("punctuation", () => {
  assert.deepEqual(values("f(a, b);"), ["f", "(", "a", ",", "b", ")", ";"]);
});

test("token positions are correct (line, column, offset)", () => {
  const tokens = tokenize("SELECT 1\n  FROM t");
  const from = tokens[2];
  assert.equal(from.value, "FROM");
  assert.equal(from.line, 2);
  assert.equal(from.column, 3);
  assert.equal(from.start, 11);
});

test("an unterminated string throws SqlError with a position", () => {
  assert.throws(() => tokenize("SELECT 'abc"), (err) => {
    assert.ok(err instanceof SqlError);
    assert.equal(err.code, "SYNTAX_ERROR");
    assert.equal(err.position.line, 1);
    assert.equal(err.position.column, 8);
    return true;
  });
});

test("an unterminated block comment throws SqlError", () => {
  assert.throws(() => tokenize("SELECT /* abc"), /unterminated block comment/);
});

test("an unrecognized character throws SqlError", () => {
  assert.throws(() => tokenize("SELECT @x"), /unrecognized character/);
});

test("describeTokens produces a readable summary", () => {
  assert.equal(describeTokens("SELECT 1;"), 'word(SELECT) number(1) punct(;) eof');
});

Chapter recap

  • Lexing cuts the character stream into tokens and records their offset / line / column.
  • Comments and whitespace produce no tokens; strings are decoded; keywords keep both the raw and the uppercase form.
  • Errors carry a position, so users know where to fix things.

Exercises

  1. Support hexadecimal numbers (0xFF): add a check in the number branch and write a test.
  2. Support # single-line comments (MySQL style). Think about where to check so it doesn't collide with operators.
  3. If a string contains a newline, does the line counter update correctly? Write a test to verify.
