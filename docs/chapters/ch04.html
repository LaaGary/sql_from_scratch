Chapter 04 / Values and types

NULL is not 0: values, types, and comparison

If you've ever been burned by WHERE status <> 'done' dropping rows where status is NULL, this chapter explains why. A database's value system has a few more rules than JavaScript's, and those rules are the foundation of every query semantic that follows.

Four runtime types

TypeJavaScript representationExampleNotes
nullnullNULLNot 0 and not an empty string — it means "unknown"
integernumber (integer)42Number.isInteger is true
realnumber (fractional)3.14Floating point
textstring'hello'UTF-8 string

In our engine, TRUE / FALSE are just 1 / 0 (same as SQLite). That saves a type and lets boolean operations use numeric comparison directly.

NULL and three-valued logic

SQL comparisons aren't just true / false; they are true / false / UNKNOWN. Any comparison with NULL on either side yields UNKNOWN:

ExpressionResultWhy
NULL = 1UNKNOWNIs "unknown" equal to 1? No idea
NULL = NULLUNKNOWNTwo unknowns aren't necessarily the same unknown
NULL IS NULLTRUEIS NULL is a dedicated test, not a comparison
NULL AND FALSEFALSEWhatever the unknown is, AND FALSE is always false
NULL OR TRUETRUESame reasoning
NOT NULLUNKNOWNThe opposite of unknown is still unknown

WHERE keeps only rows whose result is TRUE. So WHERE price <> 100 does not select rows where price IS NULL. They are excluded not because they "aren't equal to 100", but because the comparison result is UNKNOWN. This is the most common NULL trap in practice.

Practical warning

If you mean "not 100, or unknown", you must say so explicitly: WHERE price <> 100 OR price IS NULL. The database won't guess for you.

Type affinity: '42' stored in an INTEGER column becomes 42

SQL is dynamically typed: a column's declared type isn't a hard restriction, it's a preference. Our applyAffinity() tries to convert values during INSERT:

Column typeInsert '42'Insert 42Insert 'abc'
INTEGER4242'abc' (stored as-is if it can't convert)
REAL4242'abc'
TEXT'42''42''abc'
BOOLEAN110 or 1 (based on truthiness)

This "lenient but predictable" conversion keeps beginners from getting stuck on type errors while preserving the behavior a database should have. If you want strict mode, change "can't convert" in applyAffinity to throw an error.

Comparison vs. ordering: two different things

SQL's = means "equal values", while ORDER BY needs a total order. The rules aren't quite the same. Our compareValues() defines the total order used for sorting: 

NULL  <  number (-∞ … +∞)  <  text (lexicographic)

So 3 < 'abc' is TRUE (numbers sort before text), but 3 = 'abc' is FALSE (different types are not equal). SQLite works the same way. This design gives us stable ordering even in mixed-type columns.

LIKE: SQL's wildcards

  • %: a string of any length (including zero).
  • _: exactly one character.
  • \%: escape; a literal %.

We implement it by translating the pattern into a regular expression. Note that SQLite's LIKE is case-insensitive for ASCII letters, so the regex gets the i flag. Before converting, escape the regex special characters, otherwise . becomes "any character".

src/values.jsJavaScript · 306 lines · step 4
/**
 * Values and types
 *
 * SQL values and JavaScript values are not the same thing; the differences are threefold:
 *
 *   1. NULL is not "no value" but a value of its own. Any comparison with NULL yields
 *      UNKNOWN (three-valued logic); only rows whose WHERE result is TRUE are kept.
 *   2. Numbers are integers (INTEGER) or floats (REAL). In SQL, 1 and 1.0 are equal,
 *      but they display and store differently.
 *   3. Types can convert (type affinity): storing '42' into an INTEGER column
 *      converts it to the number 42.
 *
 * This file centralizes those rules so parser / executor / storage share one set of
 * definitions instead of each implementing comparison separately and drifting apart.
 */

/** Type affinities a column can declare. */
export const AFFINITY = {
  INTEGER: "INTEGER",
  REAL: "REAL",
  TEXT: "TEXT",
  BOOLEAN: "BOOLEAN",
  BLOB: "BLOB",
};

/**
 * Map the type name in CREATE TABLE to a type affinity.
 * Rules follow SQLite's affinity concept, simplified to five kinds.
 * @param {string} typeName
 */
export function affinityOf(typeName) {
  const name = String(typeName || "").toUpperCase();
  if (name === "INTEGER" || name === "INT" || name === "BIGINT") return AFFINITY.INTEGER;
  if (["REAL", "DOUBLE", "FLOAT", "NUMERIC", "DECIMAL"].includes(name)) return AFFINITY.REAL;
  if (name === "BOOLEAN" || name === "BOOL") return AFFINITY.BOOLEAN;
  if (name === "BLOB") return AFFINITY.BLOB;
  return AFFINITY.TEXT;
}

/**
 * Return the runtime type name of a value.
 * @param {unknown} value
 * @returns {"null"|"integer"|"real"|"text"}
 */
export function typeOf(value) {
  if (value === null || value === undefined) return "null";
  if (typeof value === "number") {
    if (!Number.isFinite(value)) throw new Error("unsupported number: " + value);
    return Number.isInteger(value) ? "integer" : "real";
  }
  if (typeof value === "boolean") return "integer"; // TRUE / FALSE count as 1 / 0
  if (typeof value === "string") return "text";
  throw new Error("unsupported value type: " + typeof value);
}

/** Whether this value is NULL. */
export function isNull(value) {
  return value === null || value === undefined;
}

/** Normalize a value to the form actually stored at runtime (boolean -> 0/1, undefined -> null). */
export function normalizeValue(value) {
  if (value === undefined) return null;
  if (typeof value === "boolean") return value ? 1 : 0;
  if (typeof value === "number" && !Number.isFinite(value)) {
    throw new Error("unsupported number: " + value);
  }
  return value;
}

/**
 * Convert any value to a number; return null when that is not possible.
 * This is the best-effort conversion used by arithmetic.
 * @param {unknown} value
 * @returns {number|null}
 */
export function toNumber(value) {
  if (isNull(value)) return null;
  if (typeof value === "number") return value;
  if (typeof value === "boolean") return value ? 1 : 0;
  if (typeof value === "string") {
    const text = value.trim();
    if (text === "") return null;
    const number = Number(text);
    return Number.isFinite(number) ? number : null;
  }
  return null;
}

/** Convert a value to text (NULL stays NULL). */
export function toText(value) {
  if (isNull(value)) return null;
  if (typeof value === "string") return value;
  if (typeof value === "boolean") return value ? "1" : "0";
  return String(value);
}

/** Convert a value to boolean: NULL is false; 0 and the empty string are also false. */
export function truthy(value) {
  if (isNull(value)) return false;
  if (typeof value === "boolean") return value;
  if (typeof value === "number") return value !== 0;
  if (typeof value === "string") {
    const text = value.trim().toLowerCase();
    return !(text === "" || text === "0" || text === "false");
  }
  return true;
}

/** Sort weight by type: NULL < number < text (matches SQLite ORDER BY). */
function typeRank(value) {
  if (isNull(value)) return 0;
  if (typeof value === "number" || typeof value === "boolean") return 1;
  return 2;
}

/**
 * Compare two values, returning a negative number / 0 / a positive number.
 *
 * This is the total order used for sorting:
 *   - NULL sorts first
 *   - numbers by magnitude
 *   - text lexicographically
 *   - numbers always sort before text
 *
 * Note: this is not SQL's equality test. A comparison with NULL yields UNKNOWN,
 * so use IS NULL to test for NULL.
 */
export function compareValues(a, b) {
  const left = normalizeValue(a);
  const right = normalizeValue(b);
  const rankA = typeRank(left);
  const rankB = typeRank(right);
  if (rankA !== rankB) return rankA - rankB;
  if (rankA === 0) return 0;
  if (rankA === 1) {
    if (left === right) return 0;
    return left < right ? -1 : 1;
  }
  if (left === right) return 0;
  return left < right ? -1 : 1;
}

/**
 * Evaluate an SQL comparison.
 *
 * Returns true / false or null (meaning UNKNOWN):
 *   NULL = 1         -> UNKNOWN
 *   UNKNOWN AND TRUE -> UNKNOWN
 *   WHERE keeps only rows that are TRUE
 *
 * @param {string} op "=" | "!=" | "<" | "<=" | ">" | ">="
 */
export function compare(op, a, b) {
  const left = normalizeValue(a);
  const right = normalizeValue(b);
  if (isNull(left) || isNull(right)) return null;
  const cmp = compareValues(left, right);
  switch (op) {
    case "=":
    case "==":
      return cmp === 0;
    case "!=":
    case "<>":
      return cmp !== 0;
    case "<":
      return cmp < 0;
    case "<=":
      return cmp <= 0;
    case ">":
      return cmp > 0;
    case ">=":
      return cmp >= 0;
    default:
      throw new Error("unsupported comparison operator: " + op);
  }
}

/** Three-valued logic AND. */
export function and3(a, b) {
  if (a === false || b === false) return false;
  if (a === null || b === null) return null;
  return true;
}

/** Three-valued logic OR. */
export function or3(a, b) {
  if (a === true || b === true) return true;
  if (a === null || b === null) return null;
  return false;
}

/** Three-valued logic NOT. */
export function not3(value) {
  if (value === null) return null;
  return !value;
}

/**
 * Convert a value for writing according to the column's type affinity.
 *
 *   INSERT INTO t (n) VALUES ('42')   -- n is INTEGER -> stored as 42
 *   INSERT INTO t (s) VALUES (42)     -- s is TEXT    -> stored as '42'
 *
 * @param {unknown} value
 * @param {string} affinity one of the AFFINITY values
 */
export function applyAffinity(value, affinity) {
  const normalized = normalizeValue(value);
  if (isNull(normalized)) return null;

  switch (affinity) {
    case AFFINITY.INTEGER: {
      const number = toNumber(normalized);
      if (number === null) return normalized; // store as-is when conversion fails (SQLite allows it too)
      return Number.isInteger(number) ? number : Math.trunc(number);
    }
    case AFFINITY.REAL: {
      const number = toNumber(normalized);
      return number === null ? normalized : number;
    }
    case AFFINITY.BOOLEAN: {
      if (typeof normalized === "string") {
        const text = normalized.trim().toLowerCase();
        if (text === "true" || text === "1") return 1;
        if (text === "false" || text === "0") return 0;
      }
      if (typeof normalized === "number") return normalized === 0 ? 0 : 1;
      return truthy(normalized) ? 1 : 0;
    }
    case AFFINITY.TEXT:
      return toText(normalized);
    case AFFINITY.BLOB:
    default:
      return normalized;
  }
}

/** Pattern characters that need escaping in a LIKE pattern. */
const REGEX_SPECIALS = "\\^$.|?*+()[]{}";

function escapeRegExp(text) {
  let out = "";
  for (const ch of text) {
    out += REGEX_SPECIALS.includes(ch) ? "\\" + ch : ch;
  }
  return out;
}

/**
 * SQL LIKE: % matches any length of text, _ matches exactly one character.
 * As in SQLite, ASCII letters are case-insensitive; other characters are case-sensitive.
 *
 * @param {string} text
 * @param {string} pattern
 */
export function likeMatch(text, pattern) {
  const source = toText(text);
  const like = toText(pattern);
  if (source === null || like === null) return null;

  let regex = "^";
  for (let i = 0; i < like.length; i++) {
    const ch = like[i];
    if (ch === "\\") {
      i += 1;
      regex += escapeRegExp(like[i] ?? "");
    } else if (ch === "%") {
      regex += "[\\s\\S]*";
    } else if (ch === "_") {
      regex += "[\\s\\S]";
    } else {
      regex += escapeRegExp(ch);
    }
  }
  regex += "$";
  return new RegExp(regex, "i").test(source);
}

/**
 * Group key for GROUP BY / DISTINCT: differing types are never treated as equal.
 * The number 1 and the string '1' get different keys.
 */
export function groupKey(values) {
  return values
    .map((value) => {
      const normalized = normalizeValue(value);
      if (isNull(normalized)) return "N";
      if (typeof normalized === "number") return "D" + String(normalized);
      return "S" + normalized;
    })
    .join(String.fromCharCode(0));
}

/** Convert a value to a string suitable for terminal display. */
export function displayValue(value) {
  const normalized = normalizeValue(value);
  if (isNull(normalized)) return "NULL";
  if (typeof normalized === "string") return normalized;
  return String(normalized);
}

/** Infer a column type from a value (used in query result metadata). */
export function inferType(value) {
  return typeOf(value);
}

Tests: pin down the semantics

Value-system tests don't need a database; calling the functions directly is enough. That also makes later debugging quick: is the comparison rule wrong, or the query pipeline?

tests/values.test.jsJavaScript · 98 lines · step 4
import test from "node:test";
import assert from "node:assert/strict";
import {
  affinityOf, AFFINITY, typeOf, toNumber, toText, truthy,
  compareValues, compare, and3, or3, not3, applyAffinity, likeMatch,
  groupKey, displayValue,
} from "../src/values.js";

test("type names map to affinities", () => {
  assert.equal(affinityOf("INTEGER"), AFFINITY.INTEGER);
  assert.equal(affinityOf("int"), AFFINITY.INTEGER);
  assert.equal(affinityOf("DOUBLE"), AFFINITY.REAL);
  assert.equal(affinityOf("VARCHAR(20)"), AFFINITY.TEXT);
  assert.equal(affinityOf("BOOLEAN"), AFFINITY.BOOLEAN);
});

test("typeOf distinguishes integer, real, text, and NULL", () => {
  assert.equal(typeOf(1), "integer");
  assert.equal(typeOf(1.5), "real");
  assert.equal(typeOf("a"), "text");
  assert.equal(typeOf(null), "null");
  assert.equal(typeOf(true), "integer");
});

test("toNumber's best-effort conversion", () => {
  assert.equal(toNumber("42"), 42);
  assert.equal(toNumber(" 3.5 "), 3.5);
  assert.equal(toNumber("abc"), null);
  assert.equal(toNumber(null), null);
  assert.equal(toNumber(true), 1);
});

test("toText and truthiness", () => {
  assert.equal(toText(42), "42");
  assert.equal(toText(null), null);
  assert.equal(truthy(0), false);
  assert.equal(truthy("0"), false);
  assert.equal(truthy("false"), false);
  assert.equal(truthy("x"), true);
  assert.equal(truthy(null), false);
});

test("compareValues: NULL first, numbers before text", () => {
  assert.ok(compareValues(null, 1) < 0);
  assert.ok(compareValues(1, "a") < 0);
  assert.ok(compareValues(2, 10) < 0);
  assert.equal(compareValues(1, 1.0), 0);
  assert.equal(compareValues("abc", "abc"), 0);
});

test("compare: comparing with NULL returns null (UNKNOWN)", () => {
  assert.equal(compare("=", null, 1), null);
  assert.equal(compare(">", 1, null), null);
  assert.equal(compare("=", 1, 1), true);
  assert.equal(compare("!=", 1, 2), true);
  assert.equal(compare("=", 1, "1"), false); // different types are not equal
  assert.equal(compare("<", 1, "1"), true);  // but numbers sort before text
});

test("three-valued logic AND / OR / NOT", () => {
  assert.equal(and3(true, null), null);
  assert.equal(and3(false, null), false);
  assert.equal(or3(true, null), true);
  assert.equal(or3(false, null), null);
  assert.equal(not3(null), null);
  assert.equal(not3(true), false);
});

test("type affinity conversion", () => {
  assert.equal(applyAffinity("42", AFFINITY.INTEGER), 42);
  assert.equal(applyAffinity("3.9", AFFINITY.INTEGER), 3);
  assert.equal(applyAffinity("3.5", AFFINITY.REAL), 3.5);
  assert.equal(applyAffinity(42, AFFINITY.TEXT), "42");
  assert.equal(applyAffinity("true", AFFINITY.BOOLEAN), 1);
  assert.equal(applyAffinity(0, AFFINITY.BOOLEAN), 0);
  assert.equal(applyAffinity(null, AFFINITY.INTEGER), null);
  assert.equal(applyAffinity("abc", AFFINITY.INTEGER), "abc");
});

test("LIKE's % and _", () => {
  assert.equal(likeMatch("JavaScript", "Java%"), true);
  assert.equal(likeMatch("Java", "ja_a"), true);
  assert.equal(likeMatch("Java", "j%a"), true);
  assert.equal(likeMatch("Java", "J%x"), false);
  assert.equal(likeMatch("a_b", "a\\_b"), true);
  assert.equal(likeMatch(null, "%"), null);
});

test("groupKey does not conflate 1 and '1'", () => {
  assert.notEqual(groupKey([1]), groupKey(["1"]));
  assert.equal(groupKey([1, null]), groupKey([1, null]));
});

test("displayValue", () => {
  assert.equal(displayValue(null), "NULL");
  assert.equal(displayValue("x"), "x");
  assert.equal(displayValue(3.5), "3.5");
});

Chapter recap

  • SQL has three-valued logic; comparing with NULL yields UNKNOWN, and WHERE keeps only TRUE.
  • Type affinity turns '42' into a number when it's stored in an INTEGER column.
  • Comparison (=) and ordering (ORDER BY) use different rules; numbers always sort before text.

Chapter glossary

Three-valued Logic
A logic system with true / false / UNKNOWN; SQL uses UNKNOWN for "don't know".
Type Affinity
A column's preference for a type; values are converted on write when possible, but it isn't a hard restriction.
Total Order
Any two values can be compared; sorting requires this relation.
